# Summary

**Working code is not finished code** —— 能跑不等于做完。

**可读性有硬标准**：**10 秒测试**——10 秒内看不出这段在干什么就是不合格。
**控制流要显式**，**避免过深嵌套**，**主路径要一眼可见**。
**函数大小**受控，**单一职责**，该提取就提取，但**不要过度拆分**。
**命名即文档**：避免歧义名；布尔名要能直读；**避免泛化的 `state`**；
用类型编码含义，而不是靠注释或约定。**避免魔法数字**，常量要代表概念。
**一行一个概念**；**避免聪明宏**与**炫技**。

**抽象必须挣得它的复杂度**：避免**过度抽象**、**过早泛化**；
在重复与抽象之间权衡，不要为了"将来可能"而抽象。

**状态与副作用**：消除**隐藏副作用**；**全局状态最小化**；
**所有权显式**；**错误处理必须一致**；**清理路径要显眼**，避免深层清理迷宫；
**状态机要长得像状态机**。

**分层**：**策略与机制分离**；**硬件访问与逻辑分离**；**硬件怪癖局部化**；
**避免布尔爆炸**与**参数爆炸**。

实现分两阶段（先让它正确、再让它清晰），并在动手前确认自己**理解局部而非假设全局**。

**控制流**：优先用**早返回**而不是层层缩进；把**异常路径**和**主路径**分开；
不要让主路径藏在 `if` 的深处。**嵌套超过三层的函数应该被重构**。
**函数大小**以"能否一眼看完"为准，长函数通常说明它在做多件事；
**函数提取**要提**有意义的整体**，不是为了缩短行数而机械切碎。

**一个函数一件事**：如果描述它需要"并且"，它就有两个职责。
**不要过早抽象**：出现第三次重复再抽象，第二次只是巧合。

**注释写"为什么"**，不写"是什么"；代码本身应该能说明"是什么"。
过时的注释要么更新要么删除——**错误的注释比没有注释更糟**。

**所有权**：谁分配谁释放、谁打开谁关闭要显式；
**转移所有权**要写在命名或注释里；不要在深层调用里悄悄释放调用者的资源。

**机制与策略分离**：把"怎么做"（机制）与"什么时候做、做多少"（策略）分开，
策略改动不应牵动机制代码。**硬件访问与业务逻辑分离**，
并把**硬件怪癖集中在一处**，不要散落各处 `if (revision == ...)`。
